Squiz — a streaming swipe watchlist

A Tinder-style watchlist for Australian streaming, built end-to-end with Claude Code.

The itch

"What should we watch tonight" looks like a solved problem. It isn't. Every streaming service recommends its own catalogue, none of them know what you've already watched on the others, and the global best-of lists keep suggesting things that don't actually stream in Australia. The search kept ending the same way at our place: scrolling, then rewatching something safe. I wanted picking a show to feel like flicking through a deck of cards, not doing research.

What it does

Squiz is a swipe watchlist. Sign in with Google, pick which streaming services you have — all the major Australian ones are covered, from Netflix and Stan through to ABC iview and Tubi, 23 in total — and swipe. Right means watched. Left means not for me. Press and hold means currently watching, and a detail view lets you save things to a watchlist for later.

The core mechanic is what happens after the swipe: every card you clear is automatically replaced with a fresh recommendation that actually streams on the same service, in Australia, checked at the moment it's dealt. The deck never runs dry, and it never suggests something you can't play tonight. It's live at squiz-nine.vercel.app.

How it's built

The stack is deliberately boring. The entire frontend is one static HTML page on Vercel — no framework, no build step, no package manager. Supabase's free tier does the heavy lifting: Google sign-in, a Postgres database with row-level security so each user can only ever touch their own data, and edge functions that pick the replacement shows. Streaming availability comes from TMDB and JustWatch, IMDb ratings from OMDb. Total running cost: zero.

I didn't write the code — Claude Code did, across many sessions. My job was the product: what a card shows, how the swipe and the four-second undo window should feel, the rule that a replacement must stay on the service you swiped from, and the content policy (no soap operas, no talk shows, no news). The engineering discipline that made those sessions compound is documentation written for the agent — CLAUDE.md files that describe the system's shape and its invariants, with a standing rule that any change making them false has to update them in the same commit.

The app became a factory

Once Squiz worked, the interesting question wasn't what feature to add next. It was how much of the app was reusable. The answer turned out to be almost all of the glue: the auth flow, the database security idioms, the edge-function shell, the SEO and social metadata, the icon pipeline, even the scheduled job that pings the free-tier database so it doesn't pause from inactivity.

So the repo now carries a Claude Code skill — a packaged playbook plus templates distilled from the working app. Point Claude Code at an empty repo, invoke the skill, answer a set of intake questions (name, purpose, brand colours, what data the app holds), and it stands up a brand-new app on the same skeleton: scaffolded from the templates, provisioned on Supabase, deployed on Vercel, Google sign-in working end to end. Every phase ends with a verification gate that has to pass before the next one starts, so the process can't quietly skip the hard parts.

The first app took the long road. Every app after it starts from the proven skeleton. That's the PM instinct applied to code: don't just ship the thing — ship the ability to make more of the thing.

What I learned

  1. Product taste is the scarce input now. An agent covers the full stack. What it can't supply is judgement about what the product should be. The hard decisions in Squiz were product decisions — the undo window, the same-service replacement rule, what to exclude from the deck — not code decisions.
  2. Docs for the agent are the new maintainability. The CLAUDE.md files, and the skill they fed, are why session twenty was as productive as session two. Write down the system's shape and invariants, keep them true, and every new session picks up exactly where the last one left off.
